# /change — Workflow крупных изменений

Аргументы: `$ARGUMENTS` — описание задачи (можно передать номер тикета, промпт ревью, или свободное описание).

Правила ниже — каркас, не привязанный к стеку. Конкретные конвенции (паттерны слоёв, где живёт бизнес-логика, команды запуска lint/тестов) — всегда брать из `CLAUDE.md`/`README`/конфигов проекта на Этапе 0, а не из общих соображений.

---

## Этап 0 — Загрузи контекст

Перед любым изменением:

1. Прочитай `MEMORY.md` и все релевантные файлы памяти из `.claude/projects/.../memory/`, если они есть.
2. Прочитай `CLAUDE.md` проекта — конвенции (как собирать/лить/тестировать, архитектурные паттерны, стиль).
3. Выполни `git status` и `git log --oneline -5` — пойми на какой ветке и что уже сделано.

---

## Этап 1 — Read-only разведка

**Не пиши код пока не прочитал.**

Для каждого затронутого модуля:

- Прочитай ключевые файлы целиком (не только затронутые строки — окружающий модуль).
- Найди все точки вызова изменяемого кода: `grep -rn "ИмяСимвола"`.
- Найди все тесты, если есть.

Выяви:

- Что сейчас делает код и почему именно так.
- Все места, которые нужно изменить (без пропусков).
- Потенциальные регрессии (что может сломаться).
- Подводные камни специфичные для проекта — узнать из CLAUDE.md/памяти или из самого кода (неочевидные инварианты, side-effects, порядок вызовов).

---

## Этап 2 — Составь план и задачи

Создай задачи через `TaskCreate` для каждого смыслового шага.

Правила декомпозиции:

- Одна задача = один файл или один логический блок изменений.
- Порядок: сначала самые рискованные (бизнес-логика/ядро), потом периферия (API/схемы/UI), потом lint.
- Последняя задача всегда: «Прогнать lint и тесты проекта».
- Предпоследняя (если изменения нетривиальны): «Обновить память».

Перед началом реализации — кратко изложи план пользователю: что меняется и почему именно так. Жди подтверждения на изменения, которые могут иметь широкий эффект.

---

## Этап 3 — Реализация

Для каждой задачи:

1. Отметь `TaskUpdate` → `in_progress`.
2. Прочитай файл перед правкой (даже если только что читал).
3. Вноси минимальные изменения — только то, что нужно для задачи.
4. Соблюдай конвенции проекта из `CLAUDE.md` (слой для бизнес-логики, стиль импортов, где живут side-effects/хуки/сигналы и как они триггерятся — многие фреймворки не вызывают их при bulk-операциях, проверь это для конкретного стека).
5. Отметь `TaskUpdate` → `completed`.

Во время реализации держи в голове:

- Симметрия: если меняешь логику в направлении A→B, проверь B→A.
- Dead code: нет ли недостижимого кода после `return`.

---

## Этап 4 — Проверка

Запусти команды lint/тестов, которые реально настроены в проекте (искать в `Makefile`, `package.json` scripts, `CLAUDE.md`, CI-конфиге — не выполнять инструменты напрямую в обход обёртки проекта, если она есть).

Если lint падает — исправляй только **новые** ошибки в изменённых файлах. Pre-existing ошибки в чужих файлах не трогай.

Проверь мысленные сценарии:

- Золотой путь: базовое использование работает корректно.
- Граничные случаи: пустые значения, null/None, финальные состояния/статусы.
- Регрессия: старые пути, которые ты не менял, не сломаны.

---

## Этап 5 — Обновление памяти

Если в процессе работы ты узнал что-то **нетривиальное** о проекте:

- Новое правило бизнес-логики.
- Скрытое ограничение или подводный камень.
- Архитектурное решение с неочевидной причиной.
- Новую точку вызова или зависимость между модулями.

→ Обнови или создай запись в памяти (тип `project` или `feedback`).

Если узнал что-то о предпочтениях пользователя → тип `user` или `feedback`.

---

## Этап 6 — Сообщение коммита

Не коммить самостоятельно. Предложи сообщение в формате Conventional Commits:

```
<тип>(<scope>): <краткое описание>
```

Типы: `feat`, `fix`, `refactor`, `chore`, `docs`, `test`.

---

## Чего НЕ делать

- Не добавляй обработку ошибок для сценариев, которые не могут произойти.
- Не вноси «попутный» рефакторинг за пределами задачи.
- Не коммить и не пушить без явной просьбы.
- Не выполняй инструменты напрямую в обход make/npm/скриптов проекта, если у проекта есть своя обёртка для запуска команд.
