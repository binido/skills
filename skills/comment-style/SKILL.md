# Комментарии и докстринги

Читатель - разработчик, который через полгода открыл файл и собирается его править. Ему
нужно знать, что сломается, если тронуть этот код. Каждый комментарий пишется для него.

Область - только комментарии и докстринги, которые ты пишешь или меняешь в текущей задаче.

## Когда нужен комментарий

Комментарий несёт факт, которого нет в коде:

- поведение внешней системы, которое выглядит нелогично. *"На битый токен платформа
  отвечает 401 и пустотой, а гостю отдаёт всё"* - без этого откат в гостя уберут как лишний.
- неочевидное свойство данных. *"Номера витков уникальны только внутри аппарата"* -
  объясняет составной ключ.
- ограничение, о которое уже спотыкались. *"Правая граница не включается, from=X&to=X
  отдаёт пустоту"* - защищает `+1`, который читается как ошибка на единицу.

Всё остальное говорит сам код через имена. Код без комментариев - нормальное состояние.

Комментарий стоит вплотную к строке, которую защищает. Почему выбран такой вариант, какие
были альтернативы, номер тикета - это текст для сообщения коммита и описания MR.

## Докстринги

Там, где у языка есть формат документации: Python `"""..."""`, JS/TS и Java/Kotlin `/** */`,
Rust и C# `///`, Go - комментарий над объявлением. Каждая функция, метод и класс получает
докстринг, если в проекте так принято или этого требует линтер. Иначе - только там, где
назначение не видно из имени.

- Первая строка - одно предложение: что делает, в третьем лице настоящего времени.
  `Создаёт хранилище`, `Забирает сегменты трасс`, `Отдаёт файлы из аргументов`.
  В Go строка начинается с имени: `// Parse разбирает строку в сегмент.`
- Дальше, через пустую строку, - только факт из списка выше: граничный случай, единицы
  измерения, когда бросает ошибку.
- Параметры описываются именами и типами. Секции `Args:` / `Returns:` / `@param` пишутся,
  только если они уже есть в проекте или их требует линтер.
- Файл начинается с импортов и кода. Докстринг модуля - одна строка и только по требованию
  линтера.

```python
def targets(argv: list[str]) -> list[Path]:
    """Отдаёт файлы из аргументов, а если их нет - изменённые в ветке."""


def fetch_orbits(sat_id: int, day: date) -> list[Orbit]:
    """Забирает витки аппарата за сутки.

    Граница - начало суток, а не "сейчас". Иначе витки исчезают к обеду.
    """
```

## Текст

- Язык - тот, на котором уже написаны комментарии в проекте. В новом проекте - русский.
- Короткие предложения простыми словами, как коллеге в чате. Имена из кода - как есть,
  в обратных кавычках там, где это принято.
- Только символы с обычной клавиатуры: `-`, `"`, `'`, `...`, `->`, `<=`, `>=`, `!=`,
  обычный пробел. Буква `ё`, знаки `№` и `°` - тоже с клавиатуры, их можно.
- Мысль заканчивается точкой. Две мысли - два предложения или запятая.
- Двоеточие - только перед настоящим списком и в технических записях (`EPSG:4326`,
  `http://`, `00:00`, `# noqa: E501`).

## Проверка перед сдачей

Задача не закончена, пока каждый комментарий и докстринг, который ты добавил или изменил,
не прошёл все пункты. Непрошедший переписывается или удаляется.

1. Несёт факт, которого нет в коде. Пересказ строки ниже - удалить.
2. Описывает код и внешний мир, а не нас. Слова-маркеры: "теперь", "раньше", "мы решили",
   "для надёжности", "на будущее", номер тикета - переписать про код или перенести в коммит.
3. Говорит сразу по делу. Начала "Эта функция...", "Важно:", "Примечание:", "NOTE:" -
   убрать, оставить само утверждение.
4. Докстринг - третье лицо, первая строка одним предложением.
5. Символы - с клавиатуры, без `;`, двоеточие только перед списком.
6. Не противоречит коду рядом. Если по пути нашёлся старый комментарий, который врёт, -
   исправить и отдельно сказать об этом пользователю.
